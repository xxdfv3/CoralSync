## 1. Окружение и доступ к MongoDB

**Что сделать:**

- Убедиться, что MongoDB запущен локально или есть строка подключения к Atlas.
- В `.env.local` задать:
  - `MONGODB_URI` — строка подключения (например `mongodb://localhost:27017/coralsync`).
  - `PAYLOAD_SECRET` — длинная случайная строка для Payload.
  - `PAYLOAD_PUBLIC_SERVER_URL` — например `http://localhost:3000`.

**Проверка:** из корня проекта можно вызвать `connectDB()` (например из временного API route или скрипта) и убедиться, что подключение успешно.

## 2. Базовый конфиг PayloadCMS

**Что сделать:**

- Создать конфиг Payload в `src/payload/` (или в корне — см. доки Payload 3). Обычно это один файл, например `src/payload.config.ts` или `src/payload/config.ts`.
- В конфиге:
  - Импортировать `buildConfig` из `payload` и адаптер БД (например `mongooseAdapter` из `@payloadcms/db-mongodb`).
  - Задать `secret: process.env.PAYLOAD_SECRET`.
  - Задать `db: mongooseAdapter({ url: process.env.MONGODB_URI })`.
  - Пока оставить `collections: []` или добавить одну минимальную коллекцию (например `Media` для загрузок), чтобы админка открывалась.

**Подсказка:** в Next.js 15 с App Router конфиг часто подключается через `getPayload` в `src/payload.ts` (или аналог) и используется в `app/admin/[[...segments]]/page.tsx`. Свежий пример — [Payload 3.0 Demo](https://github.com/payloadcms/payload-3.0-demo) или [документация Payload — MongoDB](https://payloadcms.com/docs/database/mongodb).

**Результат:** после `npm run dev` админка должна открываться по `/admin` и подключаться к MongoDB.

## 3. Коллекции Payload под каталог (titles, genres, media)

**Что сделать:**

- Добавить коллекции по одной, начиная с простых:
  - **Media** — для изображений (постеры, аватарки). Часто идёт из коробки или из доки.
  - **Genres** — справочник жанров (название, slug).
  - **Titles** — аниме/фильмы/сериалы: поля (название, тип, описание, связь с жанрами, постер из Media, год, кол-во эпизодов и т.д.).
- Для каждой коллекции задать `slug`, поля, при необходимости access control (кто может создавать/редактировать).

**Результат:** в админке можно создавать и редактировать жанры и тайтлы; данные хранятся в MongoDB.

## 4. Better Auth: хранение пользователей и сессий в MongoDB

**Что сделать:**

- В [документации Better Auth](https://www.better-auth.com/docs) найти раздел про database adapter для MongoDB.
- Установить адаптер (если отдельный пакет) и в `server/auth.ts` добавить в конфиг `database: { ... }` с подключением к той же MongoDB (можно использовать ту же `MONGODB_URI` или отдельную БД/коллекции).
- После этого пользователи и сессии будут храниться в БД; при желании можно включить сохранение сессий в Redis (см. комментарии в `server/auth.ts`).

**Результат:** регистрация/вход создают записи в MongoDB; сессии можно инвалидировать и привязать к пользователю.
