# Админка CoralSync (Payload)

Описание назначения админки, коллекций и того, что в ней нужно делать и как.

---

## Назначение админки

Админка (`/admin`) предназначена только для **управления каталогом и контентом**:

- ведение каталога тайтлов (аниме, фильмы, сериалы);
- справочники жанров и студий озвучки;
- медиафайлы (постеры);
- пользователи, которые имеют доступ в админку.

Обычные пользователи сайта в админку не заходят. Создание тайтлов пользователями и управление «моим списком» (статусы, обложки) делается на сайте через отдельные страницы и фичи.

---

## Вход в админку

- **URL:** `http://localhost:3000/admin` (или ваш `PAYLOAD_PUBLIC_SERVER_URL` + `/admin`).
- **Первый пользователь:** при первом заходе Payload предложит создать первого пользователя (email + пароль). Это и есть админ-аккаунт для входа в `/admin`.
- **Дальнейшие входы:** только пользователи из коллекции **Users** в Payload могут авторизоваться в админке. Пользователи Better Auth (сайт) сюда не подставляются — это отдельная система.

---

## Коллекции в админке

| Коллекция | Назначение |
|-----------|------------|
| **Тайтлы** | Каталог: аниме, фильмы, сериалы. Одна запись — один тайтл в каталоге. |
| **Медиа** | Загруженные файлы (постеры и т.д.). Используются в полях «Постер» у тайтлов. |
| **Жанры** | Справочник жанров. Подключаются к тайтлам через поле «Жанры». |
| **Студии озвучки** | Студия, которая делала озвучку (дубляж). |
| **Пользователи** | Учётные записи для входа в админку (не пользователи сайта). |

Пользовательские списки (статусы «смотрю», «просмотрено» и т.д.) в админке не ведутся и через админку не удаляются.

---

## Что делать в админке и как

### 1. Жанры

**Зачем:** чтобы у тайтлов были жанры, сначала нужно завести справочник.

**Как:**

1. В боковой панели открыть **Жанры**.
2. Нажать **Create New**.
3. Заполнить **Название** (например «Комедия», «Драма», «Фэнтези») и при необходимости **К какому типу тайтла относится**.
4. Сохранить.

Повторить для всех нужных жанров. Позже можно добавлять новые и при необходимости править.

**Если при сохранении жанра возникает ошибка 400 (slug):** в коллекции жанров поле `slug` больше не используется. Если в MongoDB в документах коллекции `genres` осталось поле `slug`, его можно удалить одной командой (mongosh или Compass):  
`db.genres.updateMany({}, { $unset: { slug: "" } })`  
После этого перезапусти dev-сервер и обнови страницу админки.

---

### 2. Студии озвучки

**Зачем:** указать студии дубляжа/озвучки (для аниме, фильмов и т.д.). Жанры студии помогают при назначении студии тайтлу (удобная фильтрация).

**Как:**

1. В боковой панели (группа «Каталог») открыть **Студии озвучки**.
2. **Create New**.
3. Заполнить **Название** и при необходимости **Жанры** (один или несколько).
4. Сохранить. Студию можно будет выбрать у тайтла в поле «Студия озвучки».

---

### 3. Медиа (постеры)

**Зачем:** перед созданием тайтлов нужны загруженные изображения для поля «Постер», либо загрузка при создании/редактировании тайтла.

**Как:**

**Вариант А — загрузить заранее:**

1. Открыть **Медиа**.
2. Загрузить файл (перетаскиванием или выбором).
3. Заполнить **Alt** (обязательное описание для доступности).
4. Сохранить. Файл появится в списке и его можно будет выбрать как постер у тайтла.

**Вариант Б — при создании/редактировании тайтла:**

1. В форме тайтла в поле **Постер** нажать загрузить новый файл (если интерфейс это поддерживает) или выбрать уже существующую запись из Медиа.

Неиспользуемые или дублирующие файлы при необходимости можно удалять из списка Медиа.

---

### 4. Тайтлы

**Зачем:** наполнение каталога — добавление и правка аниме, фильмов, сериалов.

**Как добавить тайтл:**

1. В боковой панели открыть **Тайтлы** (группа «Каталог»).
2. Нажать **Create New**.
3. Заполнить поля:
   - **Название** (обязательно) — основное название;
   - **Тип** — Фильм / Мультфильм / Сериал / Мультсериал / Аниме;
   - **Дата выхода** — при необходимости;
   - **Кол-во эпизодов** — для аниме/сериалов, при необходимости;
   - **Жанры** — выбрать один или несколько из справочника Жанры;
   - **Студия озвучки** — при необходимости (одна или несколько);
   - **Постер** — выбрать из Медиа или загрузить новое (и заполнить Alt в медиа);
   - **Описание** — при необходимости.
4. Сохранить.

**Как отредактировать тайтл:**

1. **Тайтлы** → выбрать запись из списка.
2. Изменить нужные поля (название, постер, описание, жанры, студии озвучки и т.д.).
3. Сохранить.

**Как удалить тайтл:**

1. Открыть тайтл.
2. Удалить через интерфейс (например кнопка Delete в форме или в списке, в зависимости от настройки Payload).

Дубликаты и ошибочные записи можно удалять так же через список/карточку тайтла.

---

### 5. Пользователи (админка)

**Зачем:** решить, кто может входить в `/admin`.

**Как добавить ещё одного админа/модератора:**

1. Открыть **Пользователи**.
2. **Create New**.
3. Указать **Email** и пароль (по логике Payload auth).
4. Сохранить. Этот пользователь сможет логиниться в админку.

Пароль при необходимости меняется через форму редактирования пользователя или смену пароля в самом Payload (если включено в конфиге).

---

## Чего в админке не делать

- **Не управлять пользовательскими списками** — записи «пользователь X добавил тайтл Y со статусом Z» не ведутся и не удаляются через админку (они либо в отдельной коллекции, скрытой/только для чтения, либо в своей БД).
- **Не путать пользователей Payload с пользователями сайта** — в коллекции **Пользователи** в Payload только те, кто заходит в `/admin`; пользователи сайта (Better Auth) хранятся отдельно.

---

## Дальнейшие улучшения (по желанию)

- **Модерация пользовательских тайтлов:** если пользователи смогут создавать тайтлы на сайте, можно добавить поле статуса (например «на модерации» / «опубликован») и в админке принимать или отклонять такие тайтлы.
- **Импорт из API:** скрипт или отдельный экран в админке для подгрузки тайтлов из AniList, TMDb и т.д. с созданием/обновлением записей в коллекции Тайтлы и загрузкой постеров в Медиа.
- **Access control:** уже сейчас в коллекциях можно настроить `access` (кто может создавать/редактировать/удалять). При появлении ролей (например «модератор» только контент, «суперадмин» всё) — ограничить доступ по ролям.

---

## Итог

- Зайти в админку: `/admin`, первый пользователь создаётся при первом заходе.
- Коллекции: **Жанры**, **Студии озвучки**, **Медиа**, **Тайтлы**, **Пользователи** — только каталог и доступ в админку.
- В админке: вести жанры и студии озвучки, загружать медиа, добавлять и править тайтлы, добавлять пользователей для входа в админку. Пользовательские списки через админку не трогать.
